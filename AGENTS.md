# TXR Save Builder

Static single-page app (Vite + React 19 + TypeScript, no backend) that builds and
edits **Tokyo Xtreme Racer (2025, UE5) `UserData_00.sav`** files entirely in the
browser: upload-and-edit and build-from-template modes, player stats, garage
(add/remove/duplicate), per-car chassis / engine swap / mileage / 12 tune kinds,
strict-legit validation with cheat warnings, and CRC-correct export download.

## Save format (verified by disassembly + exhaustive round-trip tests)

- File layout: `[CMTA 4B][GVAS payload][00 00 00 00 + u32LE CRC]` (total 8B footer).
- Footer = **CRC32-IEEE of `file[4:-4]`** (i.e. GVAS + 4 zero bytes), stored little-endian.
  Confirmed in `TokyoXtremeRacer-Win64-Shipping.exe` (slicing-by-8 CRC32 table).
- GVAS is UE5.4+ property-tag format (complete type names in node trees), engine 5.6,
  save version 3, 84 custom-version GUIDs, one `0x00` separator byte after `saveGameType`.
- Fixed-size engine structs: Vector/Rotator 24B (3×f64), Quat 32B, LinearColor 16B,
  DateTime 8B, Guid 16B. Everything else game-specific is custom (nested props).
- Map values/keys: bools are 1 byte inside containers (0 bytes at tag level, flag-encoded).
- uesave JSON uses `Name_0` suffixes; **binary property names have NO suffix**
  (`user_info`, `Cp`, `TuneInfos`, `EquipLevel`, ...).
- `MyCars` = Map int->struct; new keys use `++MyCarIdSrc` (never reuse deleted ids);
  `SelectedMyCarId` must reference an existing key.

## Repo layout

- `src/lib/` — codec, no dependencies, no UI imports:
  - `crc32.ts` (IEEE table), `txr.ts` (CMTA unwrap/wrap/verify),
  - `gvas.ts` (binary <-> `SaveDoc` codec; unknown types echo as raw bytes),
  - `types.ts` (document model; tags/flags/order preserved for echo).
- `src/data/` — game tables, no dependencies:
  - `cars.ts` (82 dealer incl. DLC `GB121` + 3 demokit + 77 buyable customs,
    display names, `imgUrl()`, `CUSTOM_BUYABLE`, `DLC_GATED`),
  - `engines.ts` (6 swaps), `tunes.ts` (12 kinds + bought-max/tuner rules),
  - `dressup.ts`, `caps.ts` (500M CP / 2500 BP legit caps vs parser maxima),
  - `validation.ts` (pure `validatePlayer/Car/Garage`, Ep/Traffic/Ot rejected).
- `src/state.ts` — doc helpers (player read/write, garage ops, CanBought bookkeeping).
- `src/components/` — `ModeSelect`, `PlayerForm`, `GarageList`, `CarEditor`
  (+`CarPicker` modal), `ValidatePanel`, `save-utils` (load/export).
- `public/template.sav` — completion-state template (1 stock ZC33S), generated by
  `mktemplate.ts` from a real save; CRC-valid.
- Root `*.ts` scripts (run with `npx tsx`, NOT part of the app bundle):
  `rtcheck.ts` (codec round-trip), `e2e.ts` (full UI flow), `mktemplate.ts`,
  `check-dlc.ts`, `verify-template.ts`.

## Rules

- `npm run build` (`tsc -b && vite build`) must pass. Keep components <350 lines.
- **Codec changes must round-trip byte-identical**: `parse -> serialize` on both
  `OptionData_stripped.sav` (6KB) and `UserData_stripped.sav` (1.5MB) test vectors
  (kept outside the repo; see `rtcheck.ts` for paths) must yield 0 diffs when unedited.
- Never write into `%LOCALAPPDATA%/TokyoXtremeRacer/...` — export via download only.
- Liveries (`BodyStickers`/`WindowStickers`/custom RGB) are out of scope by design
  (version-fragile binary blobs); dress-up IDs only.
- Thumbnails hotlink `https://ddm999.github.io/txr25info/img/car/...` (game assets
  © Genki, no license grant — do NOT vendor). Missing art falls back to code tiles;
  the picker credit line must stay. Coverage checker lives outside the repo.
- AES key / `.usmap` / pak-extraction scratch lives outside the repo
  (`Temp\opencode\txrthumb`, `txr_test\aeskey.txt`) — never commit keys or game assets.
